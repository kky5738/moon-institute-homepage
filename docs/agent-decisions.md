# 프로젝트 결정 및 정책 기록

이 문서는 작업 상태와 분리해 계속 적용되는 인증 정책과 사용자 결정을 보존한다. 현재 작업은 [Codex 작업 계획](./agent-work-plan.md), 완료 기록은 [2026년 작업 이력](./agent-work-history-2026.md)을 확인한다.

## 인증 입력 정책 (OWASP 기준)

- 기준 문서: [OWASP Email Validation and Verification Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html), [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html), [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 이메일:
  - 특정 국내·해외 포털 도메인 목록으로 가입을 제한하지 않고, 명백히 잘못된 형식만 거부해 유효한 기관·학교·자체 도메인을 넓게 허용한다.
  - 도메인 부분은 소문자로 정규화하되 원본 이메일은 표시·발송용으로 보존하고, 가입·로그인·복구에서 동일한 비교 정책을 사용한다.
  - 이메일을 로그인 아이디로 사용하기 전에 소유권을 확인한다. 확인이 끝나지 않은 계정은 관리자 승인 여부와 관계없이 로그인할 수 없다.
  - 이메일 확인과 비밀번호 재설정 토큰은 Supabase Auth에 위임하며, 애플리케이션 DB에 별도 토큰을 저장하거나 전체 확인 URL을 로그에 남기지 않는다.
- 비밀번호:
  - MFA가 없는 현재 서비스에서는 최소 15자, 최대 128자로 허용하고 초과 입력을 자동으로 잘라내지 않는다.
  - 유니코드·공백·특수문자를 포함한 모든 문자를 허용하며 영문자·숫자·특수문자 조합 규칙이나 금지 특수문자 목록을 두지 않는다.
  - 비밀번호 원문과 해시는 애플리케이션 DB에 저장·로그·응답하지 않고 Supabase Auth에 저장과 검증을 위임한다.
  - 회원가입과 비밀번호 변경에서 같은 길이 정책을 적용하고 Supabase Auth의 비밀번호 정책과 일치시킨다.
  - 일반적이거나 유출된 비밀번호 차단과 MFA 적용 여부는 `WAITING-07` 보안 작업에서 검토한다.
