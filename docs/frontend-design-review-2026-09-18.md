# 프런트엔드 UI·UX 평가와 디자인 개선안

> 방향 수정: 사용자 후속 의견에 따라 최종 제품 방향은 ‘문선명 연구를 위한 학술연구 플랫폼’으로 변경했다. 이 문서의 현황 진단은 유지하되, 5~7절의 ‘연구 열람실’ 중심 디자인·동선 제안은 [학술연구 플랫폼 수정안](academic-platform-direction-2026-09-18.md)으로 대체한다. 자료 탐색과 기존 회원 연구 글을 기반으로 향후 학술 토론을 연결한다.

평가일: 2026-09-18. 결론: 기본 탐색 구조는 갖췄지만, 디자인 공모전 출품작으로는 콘텐츠의 실체, 고유한 시각 언어, 화면별 완성도가 부족하다. 우선순위는 **빈 영역 제거 → 읽기 동선 정리 → 타이포그래피와 모바일 결함 수정 → 검증된 원문으로 차별화**다.

## 1. 평가 범위와 기준

로컬 개발 서버에서 홈을 데스크톱 1280×720 및 모바일 390×844로 확인했다. 모바일 메뉴, 자료 목록→자료 상세 이동을 직접 확인했다. 홈·내비게이션·푸터·주제 상세·자료 목록/상세·공지·연구 게시판·문의 폼 코드를 검토했다. 관리자, 로그인 전체 과정, 폼 실제 제출, 실제 기기, 배포 성능, 전체 키보드/스크린리더 검증은 범위에 포함하지 않았다. 개발 도구 배지는 제품 UI 평가에서 제외했다.

공모전 평가의 참고 기준은 [Webby Awards의 공식 웹사이트 심사 기준](https://www.webbyawards.com/judging-criteria/)이다. 콘텐츠, 구조와 탐색, 시각 디자인, 기능, 상호작용, 혁신, 전체 경험을 살피되 연구소의 목적에 맞게 아래 다섯 축으로 묶었다. 아래 평가는 공식 심사 점수나 사용자 테스트 결과가 아닌, 화면·코드 증거에 근거한 휴리스틱 판단이다. 수상 가능성을 수치로 추정하지 않는다.

| 평가 축 | 현 상태 | 근거 | 출품 수준으로 끌어올릴 조건 |
|---|---|---|---|
| 시각적 완성도 | 기본 정돈, 정교함 부족 | 같은 카드·배지·알약 버튼 반복, 큰 보라색 면적, 모바일 어절 분리 | 한글 조판, 강약, 공통 간격·폭, 각 콘텐츠에 맞는 레이아웃 |
| 탐색과 과업 | 경로 존재, 우선순위 불명확 | 주제보다 연표가 먼저 나오고, 영상 빈 상태가 자료보다 먼저 등장 | 첫 화면에서 주제 선택, 두 번 이내 클릭으로 실제 읽을 자료 도달 |
| 콘텐츠·신뢰 | 가장 큰 약점 | 자료 본문보다 이용 안내가 길고, 표본 기록을 홈 핵심으로 배치 | 공식 원문·출처·해설·편집 기준을 연결한 대표 자료 |
| 독창성·정체성 | 출품 차별성 부족 | 일반적인 기관 템플릿 문법, 단색 히어로 이미지 | 기록의 맥락을 읽게 하는 연표→원문 연결을 고유 경험으로 발전 |
| 접근성·기능 품질 | 기반 양호, 추가 검증 필요 | 본문 바로가기·포커스·동작 줄이기·정지 버튼 존재, 모바일 버튼 결함 | 반응형·대비·키보드·상태 전환 검증, 실환경 성능 측정 |

현재의 강점은 주제→자료→다음 자료 구조, 차분한 기본 색상, 의미 있는 연표 탐색, 기본 접근성 처리다. 이 구조를 유지하고 화면에 드러나는 정보의 양과 순서를 편집하는 것이 가장 효율적이다.

## 2. 가장 먼저 고칠 다섯 가지

### P1. 모바일 자료 카드의 주요 버튼 높이

관찰: 390px 자료 목록에서 ‘해설과 함께 보기’가 얇은 띠처럼 보인다. 원인 후보는 `MaterialArchiveCard.tsx`의 세로 flex 컨테이너 안에서 CTA에 적용한 `flex-1`이다. 높이 `h-11`과 flex basis의 조합을 실제 computed style로 재확인해야 한다. 좁은 화면에서는 flex 확장을 제거하고 `min-height:44px`을 보장하며, 가로 배치에서만 필요한 너비 확장을 적용한다. 320/390/420/768px에서 실제 클릭 영역을 검증한다.

### P1. 내용이 없는 영상 영역과 연결

`VideoContentSection.tsx`는 실제 영상 조회 없이 항상 ‘현재 등록된 영상 자료가 없습니다’를 출력한다. 홈의 소개 문장은 ‘확인할 수 있습니다’라고 약속한다. 자료 상세의 ‘영상 콘텐츠 보기’도 이 빈 영역으로 돌아온다. 영상이 없으면 홈 섹션과 관련 CTA를 함께 숨긴다. 단순 CSS 숨김으로 빈 랜드마크를 남기지 않는다. 기존 `/#media` 링크도 동시에 정리한다. 공개 영상이 생길 때 제목·대표 이미지·재생 시간·자막 유무가 있는 실제 항목으로 노출한다.

### P1. 자동 히어로의 불필요한 높이와 전환

`HomeHeroSection.tsx`는 `100svh`와 `justify-between`으로 제목과 하단 카드를 멀리 떼어놓는다. 390×844 화면에서 설명과 카드 사이에 큰 빈 공간이 생기고, 다음 섹션은 보이지 않는다. 6초마다 같은 세 연구 주제를 전환한 뒤 하단 주제 카드에서 다시 반복한다. 정적 소개문, 주요 버튼 하나, 보조 텍스트 링크 하나로 줄인다. 모바일은 콘텐츠에 맞는 높이, 데스크톱은 480~560px 전후를 시작값으로 삼아 다음 주제 영역의 존재가 보이게 조정한다.

`public/images/home/img1.jpg` 원본은 단색 이미지임을 확인했다. 사진 로딩 실패로 단정할 수 없다. 사진을 쓸 경우 이용 권한과 출처가 확인된 실제 자료 한 장만 선택한다. 사진이 없으면 단색 이미지를 내려받는 대신 CSS와 조판만으로 완결한다.

### P2. 동일한 문의 동선의 과도한 노출

헤더 ‘문의/참여’와 ‘참여 신청’, 하단 문의 버튼과 세 참여 카드, 푸터의 여러 링크가 같은 `/contact`로 이동한다. 헤더는 문의 링크 하나, 홈 끝에는 작은 문의 행 하나로 줄인다. 참여·후원에 별도 목적을 줄 경우에는 폼의 해당 문의 유형이 미리 선택되어야 한다. 현재 폼 기본값은 항상 일반 문의다.

### P2. 연표를 축소하고 실제 자료를 앞세우기

홈의 두 번째 섹션은 299건의 표본 기록이다. 데스크톱에서도 초기 축에 1920~1940 정도만 보이고, 두 사건 점 사이가 크게 비어 있다. 기록 수는 많지만 처음 보이는 정보의 밀도는 낮다. 홈에서는 공식 확인된 대표 기록 3개 또는 작은 연표 입구만 보여주고, 상세 탐색은 생애 주제 페이지로 이동한다. 샘플 기록을 검증 없이 ‘공식 기록’으로 바꾸거나 라벨만 숨기면 안 된다. 기존 전체 목록의 접기 기능은 유지할 가치가 있다.

## 3. 숨기기·축소·유지·개선 판정

| 영역 | 판정 | 구체적 변경 |
|---|---|---|
| 빈 영상, 영상 없는 곳으로 가는 링크 | 숨기기 | 공개 콘텐츠가 있을 때만 노출 |
| 영문 섹션명, 장식용 번호·배지, 금색 강조 | 축소 | 영문은 브랜드 보조 표기에 한정. 실제 순서에만 숫자 사용 |
| 히어로 슬라이드, 주제별 전체 너비 버튼, 문의·참여 대형 그라데이션 | 축소 | 정적 소개 + 주제 텍스트 링크 + 작은 문의 영역 |
| 주제→자료→다음 자료, 본문 바로가기, 접힌 전체 연표 | 유지 | 연구 활동과 접근성에 직접 기여 |
| 자료 카드와 상세, 푸터, 문의 폼 | 개선 | 중복 요약 통합, 원문 우선, 명칭 통일, 필수/선택 안내 |

주제와 자료는 삭제 대상이 아니다. 같은 내용을 여러 표면에서 반복하는 것을 줄이는 것이 목적이다.

## 4. 페이지별 추가 점검

| 화면 | 발견 사항 | 개선 방향 |
|---|---|---|
| 공통 헤더 | 연구 주제·연구 게시판 구분 설명 부족. 상세에서는 `pathname === href` 비교로 상위 메뉴의 현재 위치 표시가 빠짐 | ‘연구 주제’와 ‘연구 글’ 역할을 명시하고 상세에서도 소속 표시. 계정은 작은 유틸리티 링크 |
| 자료 목록 | ‘자료 아카이브’로 들어가면 ‘홍보자료’. summary와 별도 Reading Guide가 같은 설명을 반복. 모바일 ‘아카이브’ 단어가 줄 중간에 갈라짐 | 명칭을 자료 아카이브로 통일. 제목·가치 요약·메타데이터만 남기고 어절 단위 줄바꿈 적용 |
| 자료 상세 | 실제 본문은 두 문장인 반면 맥락·해설·읽기 포인트·영상 안내가 길다. 모바일 첫 화면은 원문 대신 연결 카드가 점유 | 짧은 자료는 제목→출처→본문→해설→다음 자료. 해설 분량은 실제 원문 밀도에 비례시킴 |
| 주제·연구 글·공지 | 주제 상세에 관련 공지가 관련 자료보다 먼저 배치. 연구 글 목록은 제목 한 줄 말줄임. 공지는 홈에 직접 노출되지 않음 | 주제의 대표 자료 우선. 모바일 연구 제목 두 줄 허용. 실제 공지 2건을 홈 하단에 간결하게 노출 |
| 문의·푸터 | 필수와 선택 구분이 약함. 최소 10자 조건이 본문 옆에 안내되지 않음. 푸터가 ‘문의 기록을 확인’하는 곳처럼 설명 | 필드 가까이에 입력 조건 표시. ‘이메일 또는 전화 한 가지’ 먼저 안내. 개인정보/운영 안내를 실제 공개 문서와 연결하고 보존 설명은 확인된 정책과 일치시킴 |

연구소 소개 독립 경로가 현재 메뉴와 페이지 목록에서 확인되지 않는다. 연구 목적·편집 원칙·운영 주체·연락 창구를 실제 제공된 원문으로 구성해야 신뢰가 생긴다. 원문이 없을 때 가상의 연혁이나 기관 정보를 채우지 않는다.

## 5. 추천 디자인: 조용한 연구 열람실

콘셉트는 ‘기록을 천천히 읽고, 맥락을 연결하는 장소’다. 흰 종이에 가까운 배경, 짙은 잉크색 본문, 제한된 보라색 강조를 사용한다. 보라색을 넓게 칠하는 대신 현재 위치와 중요한 행동을 알려주는 데 쓴다. 화면 면적 기준 중립색 약 85~90%, 연보라 보조면 약 5~10%, 진보라 강조 약 5%를 초기 미술 방향으로 삼되 기계적인 비율로 강제하지 않는다.

| 역할 | 제안 토큰 | 사용 위치 |
|---|---|---|
| 종이 배경 | `#F7F6F2` | 페이지 바탕, 따뜻한 중립색 |
| 표면 / 구분선 | `#FFFFFF` / `#DDD9E2` | 자료 읽기 영역 / 얇은 구분선 |
| 본문 / 보조 글 | `#27232D` / `#68616F` | 제목·본문 / 날짜·출처 |
| 핵심 보라 / hover | `#584477` / `#42325D` | 주요 버튼, 활성 링크, 초점 |
| 연보라 | `#EEE9F3` | 선택 영역, 작은 강조면 |

금색은 기본 UI에서 제외한다. 특정 원문 이미지에 금색이 있어도 사이트 전체의 두 번째 강조색으로 확장하지 않는다. 흰색 위 `#C8A96B`는 약 2.3:1 수준이므로 현재 금색 작은 글자는 별도 대비 점검이 필요하다.

서체: 제목은 한국어 명조 계열, 본문과 조작부는 한국어 고딕 계열을 제한적으로 조합한다. 시안은 시스템의 명조/고딕 대체 글꼴을 사용한다. 최종 배포에서는 라이선스가 확인된 한글 폰트와 필요한 굵기만 선택한다. 현재 Arial/Helvetica/Georgia 지정만으로는 한국어 서체 경험을 통제하기 어렵다.

| 규칙 | 데스크톱 | 모바일 |
|---|---|---|
| 본문 폭 | 콘텐츠 1120~1200px, 읽기 본문 640~720px | 좌우 여백 20px |
| 히어로 제목 | 48~60px, 행간 1.2~1.3 | 32~36px, 어절 단위 줄바꿈 |
| 본문 | 16~18px, 행간 1.7~1.85 | 16px 이상 |
| 섹션 간격 | 72~96px | 40~56px |
| 컨트롤 | 최소 높이 44px, 모서리 4~8px | 동일, 길어지면 줄바꿈 |

둥근 카드와 그림자를 모든 섹션에 쓰지 않는다. 연구 주제는 구분선으로 나눈 편집형 3열, 자료는 읽기 목록, 공지는 짧은 행으로 표현한다. 모양이 콘텐츠의 역할을 구별해야 한다.

## 6. 홈 정보 구조와 문구

1. **작은 헤더 + 정적 소개**: ‘문선명 연구소 / 생애, 말씀, 업적을 연구합니다.’ 설명은 ‘연구 주제와 공개 자료를 살펴보세요.’ 주요 행동 ‘연구 주제 살펴보기’, 보조 ‘자료 아카이브’.
2. **세 연구 주제**: 생애·말씀·업적의 명확한 입구. 두 줄 이내 설명과 각 주제 링크. 기존 문구에서 기능 설명을 줄이고, 원문 확보 후 실제 연구 질문으로 교체.
3. **먼저 읽을 자료**: 실제 공개 자료 3건. 현재는 안내 자료임을 정확히 표시. 원문을 확보하면 출처와 해설이 있는 대표 자료로 교체.
4. **기록 탐색 + 소식**: 검증된 대표 연표의 작은 입구, 최신 공지 2건. 표본 연표를 출품용 사실 자료로 사용하지 않음.
5. **문의 + 작은 푸터**: 한 문장과 링크 하나. 운영 주체·문의·개인정보 안내는 실제 확인된 정보만 표기.

제안 문구는 인터페이스 편집안이다. 인물의 역사·사상에 관한 새로운 사실 주장은 추가하지 않는다. 동봉 시안은 방향을 보여주는 축약안이며, 공지나 원문을 가상으로 생성하지 않았다.

## 7. 공모전 수준의 차별화

보라색과 명조만으로 수상 경쟁력을 만들 수는 없다. 이 연구소에서만 가능한 경험은 **시기의 기록을 고르고, 그 기록의 원문과 해설을 함께 읽는 과정**이다. 기존 연표를 기반으로 실제 출처가 연결된 기록 한 묶음을 높은 완성도로 편집하는 것이 유효하다. 과도한 3D, 스크롤 강제 이동, 커서 장식, 자동재생은 추가하지 않는다.

이 방향의 성립 조건은 검증된 원문과 편집 관점이다. 원문이 없는 상태에서 기능 소개문을 늘리면 공모전의 콘텐츠와 전체 경험 기준을 충족하기 어렵다. 최초 대표 자료 3건의 품질을 먼저 확보해야 한다.

## 8. 구현 순서와 검수 기준

아래 시간은 원문과 방향이 확정된 뒤의 작업자 기준 추정치이며 보장 일정이 아니다. 이번 작업에서는 평가 문서와 시안만 만들고 실제 앱 코드는 변경하지 않았다.

| 순서 | 작업 | 예상 작업 시간 | 완료 기준 |
|---|---|---|---|
| 1 | 빈 영상·중복 CTA 정리, 모바일 버튼·줄바꿈 수정 | 2~4시간 | 빈 영상으로 향하는 내부 링크 없음, 320px부터 버튼 높이 확보 |
| 2 | 히어로 축소, 주제·자료 우선 순서, 연표 이동 | 4~8시간 | 홈에서 관심 주제와 공개 자료까지 각각 1~2회 클릭 |
| 3 | 색·서체·폭·간격·푸터 통일 | 4~8시간 | 홈·목록·상세·폼에서 같은 조판 규칙 적용 |
| 4 | 공식 원문·출처·소개문 편집 | 원문 수령 후 4~8시간, 사실 검수 별도 | 주제별 대표 자료 1건 이상, 출처와 이용 권한 확인 |
| 5 | 실제 기기·접근성·배포 성능 검수 | 3~5시간 | 키보드 전 경로, 확대 200%, 모바일 터치, 오류 상태, 로딩 검증 |

접근성 목표는 WCAG 2.2 AA를 기준으로 일반 텍스트 4.5:1, 큰 글자 3:1 대비를 확인한다. AA의 포인터 목표 최소 크기는 예외 조건을 포함해 24×24 CSS px이며, 이 프로젝트는 사용 편의를 위해 44px를 설계 목표로 둔다. 44px를 AA 전체의 필수 기준으로 혼동하지 않는다. 출처: [텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [포인터 목표 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

홈을 5초 보여준 뒤 처음 보는 사람이 ‘무엇을 연구하는 곳인가’, ‘어디서 읽기 시작하는가’를 말할 수 있는지 확인한다. 서로 다른 이용자 5명에게 관심 주제→첫 자료 찾기를 요청하고, 완료 여부와 막힌 지점을 기록한다. 이는 앞으로 수행할 테스트 제안이며 이번에 실시한 결과가 아니다.
