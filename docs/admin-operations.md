# 관리자 운영 안내서

현재 홈페이지의 단일 관리자 기능을 안전하게 사용하는 방법을 정리한다. 관리자 경로는 모두 로그인이 필요하며, 계정 값은 문서가 아닌 배포 환경 변수로 관리한다.

## 1. 로그인과 이동

1. `/login`에서 관리자 아이디와 비밀번호를 입력한다.
2. 로그인 후 `/admin`에서 `게시글 관리`, `문의 관리` 또는 `회원 관리`로 이동한다.
3. 공개 화면을 확인할 때는 상단의 `사이트 보기`를 사용한다.
4. 작업을 마치면 `로그아웃`을 누른다.

관리자 로그인은 `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `AUTH_SECRET` 환경 설정을 사용하는 단일 계정 방식이다. 연구자 계정과 별개이며 관리자 계정 추가·비밀번호 변경 화면은 없다.

## 2. 게시글 운영

### 새 게시글 작성

1. `/admin/posts`에서 `새 게시글`을 누른다.
2. 제목, slug, 본문과 카테고리를 입력한다. 요약은 선택 사항이다.
3. `임시저장`을 누르면 공개 페이지에는 보이지 않는다.
4. `공개하기`를 누르면 선택한 공지사항 또는 홍보자료 영역에 공개된다.

카테고리는 게시판 종류를 함께 결정한다. 공지 카테고리는 공지사항 글, 홍보자료 카테고리는 자료 아카이브 후보 글로 저장된다. 홍보자료는 `src/lib/material-guides.ts`에 해설이 명시적으로 연결된 경우에만 자료 아카이브에 노출된다. 활성 카테고리가 없으면 게시글을 저장할 수 없다.

### 게시글 상태

| 화면 표시 | 의미 | 공개 페이지 노출 |
| --- | --- | --- |
| 초안 | 작성·검토 중 | 노출 안 됨 |
| 공개 | 방문자에게 공개 | 노출됨 |
| 보관 | 운영 기록으로 보존 | 노출 안 됨 |

상태는 선택창으로 직접 지정하지 않는다. 작성·수정 화면의 `임시저장`과 `공개하기` 버튼, 관리자 목록의 `보관` 동작이 내부 상태를 결정한다.

### 수정과 보관

- `/admin/posts`의 `수정`에서 관리자 게시글의 제목, slug, 요약, 본문과 카테고리를 바꿀 수 있다.
- 목록이나 수정 화면의 `보관`은 글을 삭제하지 않고 상태를 `보관`으로 바꾼다.
- 보관한 관리자 글도 목록에 남으며 수정 화면에서 다시 임시저장하거나 공개할 수 있다.
- 회원 연구 글은 관리자 목록에서 확인하고 공개 글을 열거나 보관할 수 있지만, 관리자가 회원의 본문을 대신 수정하지 않는다.
- 별도 삭제, 자동 저장, 수정 이력 기능은 없다. 큰 수정 전에는 현재 내용을 별도로 보관한다.

## 3. slug 관리와 연결 확인

관리자 게시글 slug는 공개 주소의 마지막 부분이다. 영문자, 숫자, 하이픈만 사용할 수 있고 저장할 때 소문자로 정규화되며 전체 게시글에서 중복될 수 없다. 회원 연구 글의 slug는 서버에서 자동 생성한다.

게시글 slug를 변경하면 기존 주소는 더 이상 해당 글을 가리키지 않는다. 변경 전후에 다음을 확인한다.

1. 공지 글은 `/notices/[slug]`, 자료 글은 `/materials/[slug]`에서 열린다.
2. 자료 아카이브에 선별한 자료라면 `src/lib/material-guides.ts`의 `slug`와 `recommendationSlugs`를 함께 변경한다.
3. seed로 관리하는 글이면 `prisma/seed.ts`의 해당 slug도 확인한다.
4. `docs/sitemap.md`의 주제·자료 연결표가 현재 값과 일치하는지 확인한다.

카테고리 slug는 관리자 화면에서 변경할 수 없다. seed 또는 DB에서 직접 변경해야 할 때는 먼저 백업과 변경 승인을 확보하고 다음 연결을 함께 갱신한다.

- `src/lib/topics.ts`의 `categoryConnections`
- `prisma/seed.ts`의 카테고리 slug
- `docs/sitemap.md`의 연결표

변경 후 `/topics/life`, `/topics/words`, `/topics/achievements`, `/materials`에서 관련 글이 예상한 주제에 표시되는지 확인한다.

## 4. 문의 운영

`/admin/inquiries`에는 일반 문의, 참여 신청, 후원 관심이 접수 순서와 상태로 표시된다.

- `검토 완료`: 확인한 문의를 검토 완료 상태로 바꾼다.
- `보관`: 문의를 삭제하지 않고 보관 상태로 바꾼다.
- `새 문의로`: 검토 완료 또는 보관 상태를 새 문의로 되돌린다.

상태 변경은 즉시 적용되며 모든 문의는 장기 보존을 전제로 남는다. 현재 목록은 문의 본문을 두 줄 미리보기로만 표시하며 별도 상세 화면이 없다. 문의 삭제, 답장 발송, 내부 메모 작성, 첨부파일 확인 기능도 없다. 이메일 또는 전화 링크로 별도 연락한 경우에도 홈페이지가 발송 기록을 자동으로 남기지 않는다.

## 5. 회원 운영

`/admin/users`에서 연구자 가입 신청의 이름, 이메일, 이메일 확인 시각, 신청일과 상태를 확인한다.

- `승인`: 이메일 확인을 마친 승인 대기 또는 비활성화 계정을 로그인 가능한 상태로 바꾼다. 미확인 계정에는 승인 버튼이 표시되지 않고 서버에서도 거부한다.
- `비활성화`: 해당 연구자의 새 로그인과 기존 연구자 세션의 계정 화면 접근을 차단한다.
- 가입 신청은 `RESEARCHER`, `PENDING`으로 고정 생성되며 연구자가 역할을 선택할 수 없다.
- 비활성화는 탈퇴와 다르다. 개인정보 처리방침 초안의 기준에 따라 비활성화일부터 최대 1년만 보존하고 운영자가 정리해야 한다.
- 승인 대기 신청은 신청일부터 30일이 지나면 운영자가 정리해야 한다. 자동 삭제 기능은 없다.
- 회원은 `/account`에서 직접 탈퇴할 수 있으며, 확인 후 계정 개인정보가 삭제되고 즉시 로그아웃된다.

승인된 회원은 `/account/posts`에서 본인 연구 글을 임시저장하거나 `/research`에 즉시 공개할 수 있다. 회원 글의 slug는 제목을 바탕으로 서버에서 자동 생성되며 회원이 직접 입력하지 않는다. 이메일 확인과 비밀번호 재설정은 Supabase Auth와 Dashboard의 SMTP 설정을 사용한다. 승인 결과 알림, 초대와 소셜 로그인은 아직 제공하지 않는다.

Supabase Auth 연결 migration과 기존 연구자 전환은 Production DB에 자동 적용하지 않는다. `WAITING-12` 승인 후 배포 점검표에 따라 적용한다.

## 6. 현재 지원 범위와 안전 수칙

- 지원: 단일 관리자 로그인, 연구자 이메일 가입·승인·비활성화·탈퇴, 회원 연구 글 임시저장·즉시 공개·수정, 관리자 게시글 작성·수정·공개·보관, 문의 조회와 상태 변경
- 미지원: 소셜 로그인, 승인 결과 이메일, 편집자 역할, 게시글·문의 영구 삭제, 버전 복원, DB 백업 복원
- 공식 인물·역사·사상 문구는 승인된 원문만 게시한다.
- 환경 변수 값과 비밀번호를 게시글이나 저장소 문서에 기록하지 않는다.
- 운영 DB 직접 수정, migration, 백업 복원, Production 배포는 별도 승인과 배포 절차에 따른다.
