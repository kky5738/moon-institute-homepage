# 문선명 연구소 홈페이지 발전 제안

## 현재 상태와 과제

홈페이지에는 연구 주제 허브와 자료 해설형 아카이브가 이미 구현되어 있다.

- 연구 주제 허브: `/topics`, `/topics/[slug]`
- 자료 해설형 아카이브: `/materials`, `/materials/[slug]`

현재 두 기능이 선명하게 와닿지 않는 가장 큰 이유는 실제 연구 콘텐츠가 충분하지 않기 때문이다. 생애·말씀·업적을 설명할 공식 원문과 개별 자료가 부족해, 화면이 연구 내용을 보여주기보다 앞으로 제공할 기능을 안내하는 상태에 가깝다.

기능의 구분도 더 명확해야 한다. 연구 주제 허브는 **무엇을 탐구하는지 보여주는 주제별 입구**이고, 자료 해설형 아카이브는 **개별 자료를 어떤 순서와 관점으로 읽을지 안내하는 읽기 경로**다. 두 기능은 같은 콘텐츠를 반복하는 것이 아니라 `주제 → 관련 자료 → 다음 자료`로 이어지는 탐색 흐름을 만든다.

새 기능을 추가하기보다 공식 콘텐츠를 채우고 두 기능의 역할을 분명히 하는 것을 다음 단계로 삼는다.

## 제안 1. 연구 주제 허브 구체화

### 목적

방문자가 게시판 종류가 아니라 관심 있는 연구 주제에서 탐색을 시작하게 한다. 현재 주제는 생애, 말씀, 업적 세 가지이며, 각 주제 페이지는 연구소가 그 주제를 어떤 범위와 관점에서 다루는지 설명하는 기준 페이지가 된다.

### 방문자가 얻어야 하는 답

각 주제 페이지는 다음 질문에 답해야 한다.

1. 이 주제는 무엇을 다루는가?
2. 왜 이 주제를 연구하는가?
3. 어떤 세부 항목으로 살펴볼 수 있는가?
4. 처음 읽을 자료는 무엇인가?
5. 더 확인할 자료와 공지는 어디에 있는가?

### 주제별 콘텐츠 구성

각 주제에 아래 내용을 갖춘다.

- 한 문장 정의: 주제의 범위를 짧고 명확하게 설명한다.
- 연구 목적: 연구소가 이 주제를 다루는 이유를 설명한다.
- 핵심 질문 3~5개: 방문자가 주제를 구체적으로 이해하도록 돕는다.
- 세부 주제: 시기, 개념, 활동 등 실제 원문에 맞는 하위 탐색 기준을 제시한다.
- 대표 자료 1~3개: 입문자가 먼저 읽을 자료를 연결한다.
- 관련 자료와 공지: 기존 `Category.slug`를 이용해 자동으로 모아 보여준다.
- 영상 및 문의 경로: 보조 수단으로 두되, 준비되지 않은 콘텐츠를 핵심처럼 강조하지 않는다.

예를 들어 “생애” 페이지는 단순히 생애 관련 자료를 모으는 데서 끝나지 않고, 연구 범위와 시기 구분, 핵심 질문, 입문 자료를 먼저 보여준 뒤 관련 자료로 연결해야 한다. 구체적인 인물·역사·사상 설명은 반드시 사용자가 제공한 공식 원문을 우선한다.

### 현재 구현과 운영 위치

- 주제 기본 문구와 연결 기준: `src/lib/topics.ts`
- 주제 목록과 상세 화면: `src/app/topics/`
- 게시글 연결 기준: `Category.slug`와 `categoryConnections`

주제 slug 또는 카테고리 slug를 변경할 때는 두 연결 값을 함께 확인한다. 주제가 크게 늘거나 관리 빈도가 높아지기 전까지 별도 `Topic` 모델은 만들지 않는다.

### 최소 콘텐츠 완료 기준

생애·말씀·업적 각 주제에 다음 내용이 들어가면 주제 허브가 실질적으로 작동한다고 본다.

- 공식 소개문 1개
- 핵심 질문 3개 이상
- 대표 자료 1개 이상
- 관련 자료 또는 공지 1개 이상

## 제안 2. 자료 해설형 아카이브 구체화

### 목적

자료를 최신순으로 나열하는 데서 벗어나, 처음 방문한 사람도 자료의 성격과 읽는 순서를 이해하도록 돕는다. 원문을 대신 설명하는 기능이 아니라, 원문에 들어가기 전 필요한 맥락과 다음 읽을 자료를 안내하는 기능이다.

### 방문자가 얻어야 하는 답

각 자료 목록과 상세 페이지는 다음 질문에 답해야 한다.

1. 이 자료는 어떤 자료인가?
2. 누구에게 필요한가?
3. 읽기 전에 알아야 할 맥락은 무엇인가?
4. 무엇에 주목해 읽어야 하는가?
5. 다음에는 어떤 자료를 읽으면 되는가?

### 자료별 콘텐츠 구성

각 자료에 아래 해설 정보를 연결한다.

- 단계 표시: 입문, 기초, 심화, 기록 중 자료 성격에 맞는 하나를 사용한다.
- 아카이브 요약: 목록에서 자료의 가치와 대상을 한두 문장으로 설명한다.
- 해설 요약: 자료의 배경과 읽기 전에 필요한 맥락을 설명한다.
- 읽기 포인트 2~4개: 본문에서 확인할 질문이나 관점을 제시한다.
- 관련 주제: 생애, 말씀, 업적 중 가장 직접적인 주제로 연결한다.
- 다음 자료 1~2개: 실제 공개된 자료만 추천한다.
- 원문 정보: 가능하면 출처, 작성·발행 시기, 자료 유형을 명시한다.

“읽는 순서”는 모든 자료를 하나의 고정된 코스로 만드는 뜻이 아니다. 처음에는 주제별 대표 입문 자료와 그다음 자료만 연결한다. 자료가 충분히 쌓였을 때만 기초·심화 경로를 확장한다.

### 현재 구현과 운영 위치

- 자료 해설, 읽기 포인트, 추천 자료: `src/lib/material-guides.ts`
- 자료 목록과 상세 화면: `src/app/materials/`
- 실제 게시글: 관리자 게시글 화면과 `Post`

추천 관계는 `recommendationSlugs`에 수동으로 관리한다. 게시글 slug를 변경하거나 자료를 비공개로 전환할 때 추천 연결도 함께 확인한다. 해설이 없는 자료는 “보관 자료” fallback으로 표시되므로, 공개 후 핵심 자료부터 해설을 추가한다.

### 최소 콘텐츠 완료 기준

자료 해설형 아카이브가 실질적으로 보이려면 최소한 다음 콘텐츠가 필요하다.

- 생애·말씀·업적의 대표 입문 자료 각 1개
- 각 자료의 공식 본문 또는 원문
- 각 자료의 해설 요약 1개
- 각 자료의 읽기 포인트 2개 이상
- 실제 공개 자료를 향한 다음 자료 연결 1개 이상

## 두 기능의 연결 흐름

방문자 탐색은 다음 흐름을 기본으로 한다.

1. 홈에서 생애·말씀·업적 중 관심 주제를 선택한다.
2. 주제 페이지에서 연구 범위와 핵심 질문을 이해한다.
3. 대표 입문 자료를 선택한다.
4. 자료 상세에서 해설과 읽기 포인트를 확인하고 원문을 읽는다.
5. 추천 자료 또는 관련 주제로 탐색을 이어간다.

홈과 각 상세 페이지의 CTA는 이 흐름을 우선하며, 준비 중인 영상이나 일반 문의 경로가 핵심 탐색을 방해하지 않게 한다.

## 다음 액션

1. 사용자가 생애·말씀·업적의 공식 소개 원문을 제공한다.
2. 각 주제의 핵심 질문과 대표 입문 자료를 선정한다.
3. 대표 자료 세 건에 실제 본문, 해설 요약, 읽기 포인트를 작성한다.
4. 콘텐츠 반영 후 홈 → 주제 → 자료 → 추천 자료 흐름을 다시 점검한다.

콘텐츠가 준비되기 전에는 데이터 모델이나 관리자 기능을 확장하지 않는다. 현재의 정적 주제·해설 설정만으로 초기 운영에 충분하다.
