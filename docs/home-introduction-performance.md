# 첫 화면 로딩 성능 기준선 — READY-65 (2026-11-12)

이번 변경은 첫 화면 콘텐츠 조회 중 표시하던 문구를 높이가 같은 검은 배경으로 바꾼다. 이미지 파일·제공 경로·캐시·요청 우선순위는 변경하지 않았다. 전송량 감소나 LCP 개선을 이 변경의 효과로 주장하지 않는다. 실제 이미지 최적화와 최종 비교는 READY-66~68에서 진행한다.

## 측정 환경과 방법

로컬 Next.js 16.2.6 production build, Node v24.14.1, 임시 PostgreSQL 17.11, Chromium 156.0.8078.80, 기존 비운영 staging private Storage를 사용했다. 운영 및 staging DB에는 migration을 적용하지 않았다. 사진은 저장소의 `src/assets/home-introduction.jpeg`를 별도 UUID object로 업로드해 사용했으며 원본은 변경하지 않았다.

사진: 1507×1848, JPEG 1,351,980 bytes. SHA-256 `78c52cd20c029fa96c20845f83fe98be31b8a7477ce65ec2585aac1049993851`. 문구는 기존 기본 문구를 사용했다. 두 빌드는 같은 DB·현재 포인터·Storage object를 공유하며 측정 중 관리자 변경은 없었다.

1. 각 빌드에서 1280×720·390×720 × 일반·저속 × 초기·반복 방문을 각각 3회 측정했다(24회씩, 총 48회). 초기 방문은 새 브라우저 컨텍스트이며 반복 방문은 같은 컨텍스트로 재방문한다. 서버는 이미 실행 중인 상태이며 첫 before 표본에는 콘텐츠 캐시 조회도 발생했다. 이후 표본은 콘텐츠 캐시 적중 상태였다. 서버 재시작 직후 캐시 미적중은 아래 별도 표로 확인했다.
2. 일반 조건은 localhost 무제한, 저속 조건은 CDP 지연 150ms·다운로드 200,000 bytes/s(1.6Mbps)·업로드 93,750 bytes/s(0.75Mbps)이다. CPU 제한은 없고 서버↔Storage 구간은 제한하지 않았다. reduced-motion을 고정했다.
3. Navigation/Resource Timing으로 HTML TTFB, 이미지 시작·TTFB·완료·전송 바이트를 읽었다. LCP/CLS는 buffered PerformanceObserver로 관측하고 이미지 decode·글꼴 준비 후 750ms까지 수집했다. 모든 표본의 LCP는 첫 화면 IMG였고 실제 이미지 네트워크 요청은 한 번이었다.
4. 이미지 주소가 HTML에 도착하는 시점은 방문 측정 뒤 같은 브라우저/네트워크에서 별도의 `fetch("/", {cache:"no-store"})` 응답을 ReadableStream으로 읽어 첫 URL 문자열 수신까지 측정했다. 반복 방문의 CDP 본문 스트리밍 제한을 피하기 위한 별도 탐침이며 실제 navigation의 이미지 시작 시각과 직접 빼서 해석하지 않는다. HTML 탐침 TTFB·완료·바이트도 로컬 원자료에 보관했다.
5. 임시 Node preload로 PostgreSQL 현재 포인터 조회와 Undici Storage info·다운로드 왕복을 분리했다. 로그에는 단계·소요 시간·응답 코드만 저장하고 SQL·URL·키·토큰·Storage 경로는 기록하지 않았다. 아래 서버 시간은 각 방문 이미지 제공 구간이며 HTML 탐침은 제외했다.

## 표시·권한 범위와 후속 비교

3초 DB 조회 지연을 적용한 390×720 production 브라우저에서 fallback 텍스트·status 0개, 검은 배경·aria-hidden=true, 콘텐츠 수신 전후 section 높이와 선언문 시작 위치 모두 720px를 확인했다. 이미지 503에서는 기존 오류 안내와 문구가 남고 다음 선언문으로 scrollY=500 이동이 가능했다. 높이/블러 CSS와 현재 적용본 검사·no-store·관리 이미지 인증은 변경하지 않았다. 200자 등 긴 콘텐츠의 기존 min-content 확장은 별도 동작이며 모든 문구 길이에서 CLS가 0이라고 일반화하지 않는다.

READY-66~68에서는 같은 사진 해시·현재 문구·뷰포트·네트워크·CPU/모션 조건과 3회 초기/반복 방문을 재사용한다. 새 표시용 파일의 해시·실제 치수·바이트도 함께 기록하고 원본 보존을 확인한다. 원본 전송량과 info 왕복을 줄이는 작업은 아직 수행하지 않았다.

로컬 원자료와 계측/브라우저 실행 스크립트는 git 제외 `outputs/ready65/`에 보관한다. 이 문서는 표본 전체를 추적 가능하게 보존한다. 이 값은 로컬 앱+staging 결과이며 운영 p50/p95, 실기기 CPU, Safari/Firefox 성능을 대표하지 않는다. 초기 프로파일러 설정 검증 중 실패한 표본은 제외하고 최종 완료된 24회씩만 사용했다. 테스트 object와 임시 자원은 정리하며 운영 DB·Storage 정책·배포는 변경하지 않는다.
