작성 화면의 중심을 입력 항목에서 글 자체로 옮긴다. 제목·본문은 하나의 원고 영역에 두고, 필요한 게시 설정과 파일 조작은 분리한다. 요약·공개 범위·글 주소 UI는 제공하지 않는다. 작성·조회는 비슷한 본문 폭과 활자를 사용하고, 게시글 영역의 버튼·링크·포커스에는 잉크 블루 #344D67을 사용한다. 홈·전역 내비게이션의 보라색은 유지한다.

아래 문제 표는 2026-11-04 구현 전 관찰 기록이다. 구현 후에는 실제 컴포넌트의 로컬 브라우저와 격리 DB로 검증했다. 실제 인증·운영 Storage·Production의 전체 흐름은 별도 검증 대상이다. 아래 공식 출처는 초기 제안 작성 때 확인한 참고 자료이며, 외부 서비스의 기능과 이 프로젝트의 구현 범위를 구분한다.

## 화면별 설계

### 작성: 원고가 먼저 보이게

1. 큰 관리 헤더를 간결하게 줄이고 원고 제목을 모바일 28px·데스크톱 32px로 표시한다. 제목에서 본문으로 바로 이어지며 요약 입력은 없다.
2. 데스크톱은 넓은 원고와 288px 보조 영역을 분리한다. 모바일은 보조 영역을 본문 아래에 둔다. 상단 작업 바에는 `임시저장`, `공개하기`와 취소만 제공하며 미리보기는 추가하지 않는다.
3. 연구자는 고정 게시 위치를 텍스트로 확인하고 관리자는 게시판·카테고리를 선택한다. 공개 범위·글 주소·슬러그 입력은 없으며 신규 주소는 서버에서 생성하고 수정 시 보존한다.
4. 이미지·첨부는 기존 파일 선택·이미지 표식 삽입 흐름을 유지한다. 긴 파일명을 줄바꿈하며 성공한 업로드는 최종 저장 재시도 때 재사용한다. 이미지 미리보기는 추가하지 않는다.
5. 저장 중에는 편집·중복 제출을 막고 오류 후 입력을 보존한다. 서버 성공 전에는 저장 완료를 표시하지 않는다. 자동 저장과 편집 이력은 제공하지 않는다.

### 조회: 제목 → 작성 정보 → 본문 → 첨부

1. 연구·공지·홍보 모두 `목록으로 → 분류 → 제목 → 작성 정보 → 본문 → 첨부` 순서를 사용한다. 과거 글의 요약 데이터는 보존하되 화면에는 요약이나 본문을 잘라 만든 대체 요약을 표시하지 않는다. 검색·공유용 메타데이터 설명은 유지한다.
2. 작성 화면과 가까운 폭으로 원고를 배치하고 본문은 모바일 16px·데스크톱 17px, 행간 1.85를 사용한다. 배경·본문은 중립색이고 잉크 블루는 해당 게시글 영역에만 적용한다.
3. 첨부는 본문 아래에서 파일명·형식·크기·다운로드 동작을 표시한다. 본문 이미지의 비율·대체 텍스트·기존 공개 권한 검사를 유지한다.
4. 홍보자료는 원문·첨부를 먼저 보여주고, 선별 자료의 해설·읽기 포인트·연관 자료를 별도 구간으로 구분한다. 홈 탐색 비활성화 정책은 유지한다.
5. 본문은 일반 텍스트와 기존 연구 이미지 표식만 처리한다. 리치 텍스트·Markdown·목차는 추가하지 않는다.

### 목록: 기존 표 구조를 다듬기

연구 목록의 `번호 | 제목 | 첨부 | 작성자 | 작성일`을 유지한다. 번호는 약하게, 제목은 가장 강하게, 첨부는 파일 아이콘 또는 개수로 표시한다. 요약문·대표 이미지는 추가하지 않는다. 모바일은 제목 아래 작성자·날짜·첨부를 묶는다. 내 글 목록은 `임시저장/공개/관리자 보관`을 텍스트로 명확히 구분하고 허용되는 보기·수정 동작만 노출한다.

## 적용 범위와 후속 기능

READY-54의 저장 처리, READY-55의 작성·수정, READY-56의 목록·상세를 로컬에서 구현·검증했다. 새 의존성·DB migration·운영 데이터 변경·배포는 포함하지 않는다. 신규 요약은 null이며 기존 요약 값은 수정 시 보존한다. 주소는 서버에서 생성하고 기존 주소는 제목 수정 후에도 유지한다.

미리보기·자동 저장·이미지 미리보기·리치 텍스트·Markdown·목차는 이번 구현에 없다. 필요한 경우 별도 요청과 계획으로 범위를 정한다.

## 검증 기준과 근거

1. 1280px·390px에서 긴 제목·본문·파일명, 가로 넘침, 키보드 초점과 텍스트 대비를 확인한다.
2. 연구·공지·홍보별 임시저장 → 수정 → 공개 → 목록 → 상세와 기존 URL·첨부 유무·보관·삭제 비노출은 격리 DB와 페이지 렌더링 테스트로 확인한다.
3. 기존 요약·대체 요약 비노출, 공유용 설명 보존과 원문·별도 해설 구분을 회귀 테스트로 확인한다.
4. 파일 접근 권한·Storage 원본과 운영 배포에서 직접 확인하지 못한 범위는 READY-18에 남긴다.
5. `npm run test:posts`, `npm run test:posts:integration`, `npm run lint`, `npm run build` 결과는 완료 이력에 기록한다.
