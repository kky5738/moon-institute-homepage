# 게시글 작성·조회 디자인 개선안

검토일: 2026-11-04 · 상태: 디자인 제안, 실제 서비스 미반영

> 초기 디자인 제안 기록입니다. 최종 색상과 제거 항목은 [agent-work-plan.md](./agent-work-plan.md)의 READY-54~56 기준을 따릅니다.

## 추천: 종이에 쓰고, 문서처럼 읽는 화면

작성 화면의 중심을 입력 항목에서 글 자체로 옮긴다. 제목·요약·본문은 하나의 원고 영역에 두고, 게시 설정은 분리한다. 공개 화면도 같은 본문 폭과 활자 체계를 사용한다. 기존 보라색은 주요 버튼과 링크에 제한하고 읽는 영역은 중립적인 종이색으로 정리한다.

현재 평가는 저장소의 JSX·CSS·저장 흐름을 확인한 결과다. 로그인한 실제 작성 화면의 브라우저 사용성 테스트는 수행하지 않았다. 아래 출처는 공식 페이지를 확인했으며, 서비스 기능 설명과 이 프로젝트에 대한 제안을 구분했다.

## 화면별 설계

### 작성: 원고가 먼저 보이게

1. 상단의 큰 `새 글 작성` 헤더를 작은 경로 표시로 줄인다. 그 아래 원고 제목을 32px 안팎으로 크게 쓴다. 요약은 선택 항목임을 표시하고 본문과 자연스럽게 이어지게 한다.
2. 데스크톱은 본문 최대 720px와 설정 약 240px를 분리한다. 상단 작업 바에 `임시저장`, `미리보기`, `공개하기`를 배치한다. 공개만 채운 보라색 버튼을 사용한다. 화면이 좁아지면 설정은 본문 아래로 접고 작업 바는 줄바꿈한다.
3. 연구자는 게시 위치가 연구 게시판으로 정해져 있으므로 불필요한 선택기를 만들지 않는다. 관리자에게만 게시판·카테고리를 제공한다. 관리자 필수 슬러그는 `글 주소`로 이름을 바꿔 설정에 유지한다. 자동 생성은 별도 동작 변경으로 취급한다.
4. 이미지·첨부는 본문 근처의 간단한 추가 동작으로 묶고, 파일별 이름·크기·저장 상태와 제거 동작을 분명하게 한다. 오류가 난 파일은 재시도할 수 있게 하되 성공한 파일을 중복 업로드하지 않는다.
5. 저장 상태는 서버 성공 응답이 있을 때만 `저장됨`으로 바꾼다. 자동 저장을 도입하지 않았다면 그렇게 보이는 문구도 사용하지 않는다. 필수 입력 오류는 항목 바로 옆과 상단 요약에 표시한다.

### 조회: 제목 → 맥락 → 본문 → 자료

1. 연구·공지·홍보 모두 `목록으로 → 분류 → 제목 → 요약 → 작성자/게시일 → 본문`의 기본 순서를 공유한다. 없는 작성자 정보나 요약은 빈 공간 없이 생략한다.
2. 본문은 약 680~760px, 데스크톱 17~18px/행간 1.8~1.9, 모바일 16px/행간 1.8을 출발점으로 검증한다. 기존 연구 조회도 이미 데스크톱 17px이므로 폰트 확대보다 작성 화면과의 일관성이 우선이다.
3. 본문 아래 첨부 영역에서 `파일명 / PDF·HWP·DOCX / 용량 / 다운로드`를 한 행에 보여 준다. 상단에는 첨부가 있을 때만 `첨부파일 n개` 이동 링크를 제공한다. 보유하지 않은 페이지 수는 표시하지 않는다.
4. 홍보자료의 원문과 해설은 구분을 유지한다. 해설·읽기 포인트·연관 자료는 본문을 압박하는 카드들 대신 명확한 별도 섹션으로 정리한다. 비활성화된 홈 탐색 기능을 이 디자인 작업으로 다시 켜지 않는다.
5. 소제목·인용 등은 실제 저장 형식이 지원할 때만 렌더링한다. 자동 목차는 소제목이 충분한 긴 글에 한해 후속 검토한다. 일반 텍스트에 가짜 소제목이나 내용을 임의 생성하지 않는다.

### 목록: 기존 표 구조를 다듬기

연구 목록의 `번호 | 제목 | 첨부 | 작성자 | 작성일`을 유지한다. 번호는 약하게, 제목은 가장 강하게, 첨부는 파일 아이콘 또는 개수로 표시한다. 요약문·대표 이미지는 추가하지 않는다. 모바일은 제목 아래 작성자·날짜·첨부를 묶는다. 내 글 목록은 `임시저장/공개/관리자 보관`을 텍스트로 명확히 구분하고 허용되는 보기·수정 동작만 노출한다.

## 적용 순서와 범위

| 단계 | 작업 | 완료 확인 |
|---|---|---|
| 1 · 추천 시작점 | 작성 헤더 축소, 원고 크기·간격 정돈, 게시 설정 분리, 작업 바, 조회·첨부 스타일 통일 | 동일한 글이 작성·조회에서 비슷한 폭과 위계를 가짐. 연구 목록의 기존 열 구조 유지 |
| 2 · 기능 확장 제안 | 공개 렌더러를 공유하는 미리보기, 선택한 이미지의 로컬 미리보기, 소제목·인용·링크 중심 최소 편집 | 미리보기 때문에 게시 상태가 바뀌지 않음. 이미지 순서와 줄바꿈이 공개 결과와 맞음. 기존 글·이미지 표식이 계속 읽힘 |
| 3 · 필요 확인 후 | 관리자 글 주소 자동 생성, 긴 글 목차 | 주소 충돌과 기존 주소 유지 규칙 검증. 제목 구조가 있는 글만 목차 생성 |

기존 `docs/agent-work-plan.md`의 READY-18에는 이미지 미리보기·범용 리치 텍스트를 제외한 결정이 있다. 이번 요청은 재설계를 위한 제안 작성이므로 기능 변경을 실행하지 않았다. 후속 구현에서 범위가 선택되면 기존 결정과 구현 범위를 함께 갱신한다. 이 문서는 실행 승인이나 READY 전환을 대신하지 않는다.

미리보기는 초안에 공개 URL을 발급하지 않는 방식으로 설계한다. 실제 업로드 권한·파일 검증·부분 실패 복구는 기존 흐름을 유지한다. 서식 편집을 도입할 때는 HTML을 그대로 실행하지 않고 허용된 문서 구조만 렌더링하며, 기존 일반 텍스트와 이미지 표식의 호환 처리가 필요하다.

## 검증 기준

1. 360px와 1280px에서 긴 제목·파일명이 가로 넘침 없이 보이고, 키보드만으로 작성·저장·미리보기 이동이 가능하다.
2. 빈 글, 제목만 있는 초안, 이미지 포함 글, 첨부 여러 개, 저장 실패 상태에서 필수 행동과 상태가 분명하다.
3. 미리보기와 공개 화면에서 제목·요약·문단·이미지·파일 순서가 일치하며 서버 검증 전 공개 완료를 표시하지 않는다.
4. 공개·임시저장·보관의 기존 권한과 수정 동작이 유지된다. 긴 글의 스크롤에서도 작업 바가 본문이나 포커스를 가리지 않는다.
5. 실제 구현 시 `npm run lint`, `npm run build`와 변경된 저장·이미지 경계에 맞는 기존 테스트를 수행한다. 이번 제안에는 애플리케이션 코드 변경이 없다.
