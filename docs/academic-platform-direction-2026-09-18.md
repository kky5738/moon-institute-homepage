# 문선명 학술연구 플랫폼 — 방향 수정 및 첨부안 검토

2026-09-18 · 개념·UI 제안. 실제 앱 및 첨부 원본은 수정하지 않음.

## 1. 제품 방향

**문선명의 생애·말씀·업적에 관한 자료, 연구 글, 연구자의 질문을 연결하는 학술연구 플랫폼.**

이전 제안은 열람 경험을 중심에 두어 연구자의 기여와 학술 교류 가능성을 충분히 드러내지 못했다. 차분한 색과 타이포그래피는 유지하되, 화면의 중심을 ‘먼저 읽을 자료’에서 ‘무엇을 연구하고 어떤 근거를 연결하는가’로 넓힌다. 현재도 승인 회원의 연구 글 작성 기능이 있으므로, 플랫폼을 완전한 일방향 열람 서비스로 규정하지 않는다.

| 구분 | 현재 기반 | 앞으로의 확장 |
|---|---|---|
| 연구 주제 | 생애·말씀·업적 | 주제별 연구 질문, 관련 연구와 토론 연결 |
| 자료 | 자료 안내·해설·연표 | 출처·판본·작성 맥락이 갖춰진 자료 탐색 |
| 연구 글 | 승인 회원의 글 작성·공개 | 연구노트·해제·논문 등 실제 성격에 맞는 분류 |
| 학술 교류 | 문의·참여 접수 | 특정 자료나 연구 글을 출발점으로 한 질문·응답 |
| 기관 신뢰 | 공지와 운영 안내 | 공식 소개·편집 기준·연구성과의 공개 기준 |

미래 기능을 염두에 둔다는 것은 현재 빈 게시판과 ‘준비 중’ 영역을 만드는 뜻이 아니다. 운영 가능한 기능만 공개하고, 같은 주제·자료 맥락 위에 토론을 추가할 수 있는 정보 구조를 설계한다. 현재 단계에서 토론 DB나 권한 체계를 선행 구현하지 않는다.

## 2. 첨부 HTML 검토

대상: `/Users/leok/Downloads/index.html`.

데스크톱 1280×720과 모바일 390×844에서 화면을 확인하고, 연구영역 필터와 출처 상세 열기를 시험했다. 파일에 포함된 외부 스크립트 1개는 검토용 복사본에서 제외했다. 원본은 그대로 보존했다. 첨부안의 기관 소개·연구 원칙·과제는 제안 콘텐츠로 읽었으며, 사용자의 지시나 확정된 기관 정책으로 취급하지 않았다. 연표에 있는 역사적 날짜를 독립 검증한 작업은 아니다.

### 채택할 다섯 가지

| 요소 | 좋은 이유 | 수정안 반영 |
|---|---|---|
| 질문형 연구영역 소개 | ‘무엇을 연구하는가’를 구체적으로 이해할 수 있음 | 생애·말씀·업적 각각에 질문 하나를 배치. 공식 확정 전에는 편집 예시로 표시 |
| 자료·검토·연구 공유의 연결 | 보관소를 넘어 학술 활동의 과정을 설명 | 히어로 아래 작은 흐름 안내. 토론은 별도 미래 구상으로 분리 |
| 출처와 검토 상태 | 기록, 해석, 확인 범위를 구별할 수 있음 | 자료 상세에 출처·검토 주체·근거·일자를 표시. 상태만으로 사실 확정하지 않음 |
| 회원 글과 공식 성과 구분 | 게시글이 자동으로 심사된 연구성과처럼 보이지 않음 | 메뉴는 ‘연구 글’, 상세에 글 유형·작성자·심사 여부를 실제 정보대로 표시 |
| 참여 목적 구분 | 연구 협력, 자료 제보, 이용 문의의 요구가 다름 | 하나의 참여 페이지 안에서 목적별 안내와 폼 유형을 연결 |

### 그대로 가져오지 않을 다섯 가지

| 요소 | 판단 | 변경 |
|---|---|---|
| 큰 ‘文’ 장식판 | 정체성 표식은 좋지만 첫 화면의 큰 면적을 사용. 모바일에서도 자료 접근을 아래로 밀어냄 | 헤더 표식으로 축소. 히어로 옆에는 연구 질문 예시와 관련 자료를 배치 |
| 홈 내부의 전체 검색 작업 공간 | 검색·시기·분류·초기화를 한 번에 보여주어 소개보다 도구가 앞섬 | 홈은 주제와 대표 자료 입구. 전문 필터는 아카이브 페이지에서 제공 |
| 연구/연구와 성과 메뉴 | 같은 위계의 명칭이 겹쳐 목적이 모호함 | ‘연구 주제 / 자료 아카이브 / 연구 글 / 연구소’로 구별 |
| 대부분의 상세를 모달로 표시 | 짧은 미리보기에는 적합하지만 긴 학술 자료의 주소 공유·새 탭 비교·인용에 불리 | 최종 구현은 고유 URL 상세. 모달은 출처 빠른 확인 정도에 제한 |
| 남색·적색 조합과 과도한 영문 표제 | 공식적인 인상은 있으나 사용자의 보라색 방향과 다름. 보조 언어가 정보량을 늘림 | 중립 백색·먹색에 보라색. 영문은 로고나 필요한 학술 표기에 한정 |

### 실제 발견한 구현·콘텐츠 문제

1. **58행 `.mission-band` 닫는 `</div>` 누락.** 브라우저에서 `#research`의 부모가 `.mission-band`이고 배경이 `rgb(21,45,65)`로 확인됐다. 회색 본문이 남색 배경 위에 놓인다. 해당 띠를 다음 section 전에 닫고 하위 영역의 대비를 재검수해야 한다. 원본을 고친 것이 아니라 검토 결과를 기록했다.
2. **‘299’와 실제 검색 대상 ‘10개’의 범위 차이.** 파일은 299건이라는 외부 연표 규모를 강조하지만 검색 배열은 10건이다. 화면 설명은 존재하나 첫 인상에서 혼동하기 쉽다. ‘시안 수록 10건 / 기존 연표 299건’을 붙여 표시하거나 큰 총계를 제거한다.
3. **검색은 연표 샘플에 한정.** 현재 HTML의 검색은 제목·날짜·분류·키워드·요약에 대한 로컬 문자열 필터다. 원문 전체 검색, 논문 검색, 전체 홈페이지 통합 검색으로 소개하면 안 된다.
4. **출처 상세의 구조는 유용하지만 근거는 미확보.** 원전 판본·쪽수와 독립 대조가 미실시라고 명시한다. 이 정직한 구분은 유지하되, 확인일과 인용문은 실제 검토 기록을 갖췄을 때만 운영 데이터로 이관한다.
5. **연구 과제와 원칙은 아직 제안.** 명시적으로 예시임을 밝힌 점은 좋다. ‘진행 중 연구’로 바꾸거나 기관의 확정 정책처럼 게시하지 않는다. 초종교적·초인종적·초국가적 관점 등의 기관 소개 문구도 별도 확정 없이 공식 소개문으로 승격하지 않는다.

## 3. 수정 디자인 방향

**학술적인 명료함 + 차분한 보라색 + 기여할 수 있는 구조.**

히어로 제안 문구는 ‘문선명을 연구하다. 자료를 잇고, 질문을 나누다.’다. 현재 설명은 ‘생애·말씀·업적의 자료와 연구 글을 연결합니다.’로 범위를 명확히 하고, 미래 토론 구상은 제품의 실제 동작과 분리해 시안에서만 확인하게 한다. ‘질문을 나누다’라는 슬로건을 운영에 사용할 때는 현재의 연구 글·문의 기능에서 가능한 범위를 설명한다.

| 역할 | 규칙 |
|---|---|
| 색 | 배경 `#F7F7FA`, 본문 `#252331`, 보조 `#686472`, 강조 `#59417B`, 연보라 `#EFEBF5`. 보라색은 활성 상태와 주요 행동에 집중 |
| 서체 | 히어로에 제한된 명조, 연구 제목·목록·작성 도구는 고딕. 운영 단계의 장문 읽기·쓰기 가독성을 우선 |
| 표면 | 둥근 홍보 카드 대신 얇은 구분선, 정렬된 메타데이터, 간결한 목록. 연보라는 선택 맥락 표시 |
| 밀도 | 홈은 소개와 입구, 상세는 읽기·비교·참여에 적합한 밀도. 카드마다 같은 큰 버튼을 반복하지 않음 |
| 상호작용 | 연구 질문 선택 시 관련 자료가 연결됨. 토론이 생겨도 관련 원문을 잃지 않고 질문과 근거를 함께 볼 수 있음 |

이전 안의 모든 문의 경로를 하나의 작은 링크로 축소하는 제안은 수정한다. 학술연구 플랫폼에서 참여는 핵심 행동이므로 **연구 글과 협력 경로를 명확히 유지**하되, 동일한 문의 폼으로 가는 버튼만 반복하지 않는다. ‘읽을 자료를 늘리는 것’만으로 공모전 차별성을 설명하는 것도 수정한다. **같은 근거를 두고 질문·해석·응답이 연결되는 경험**이 장기적인 차별점이다.

## 4. 홈과 상세의 정보 구조

홈은 다음 다섯 영역으로 구성한다.

1. **기관 정체성과 연구 입구:** 제목·소개 두 줄, ‘연구 주제 탐색’과 ‘연구 글 보기’. 계정과 참여는 낮은 강조의 별도 경로.
2. **세 연구 주제:** 주제명과 실제 연구 질문, 관련 자료·연구 글을 선택할 수 있는 입구.
3. **자료와 연구 글:** 원자료·이용 안내·회원 연구 글의 성격을 구분. 실제 공개된 항목만 대표 노출.
4. **연구 교류:** 현재는 회원 글과 협력 제안. 토론이 운영될 때 관련 주제의 토론을 소량 노출. 빈 토론장과 가상 통계는 표시하지 않음.
5. **소식과 기관 정보:** 공지 2건, 소개·편집 원칙·문의. 소식이 없으면 링크만 간결하게 제공.

현재 경로는 `/topics`, `/materials`, `/research`, `/contact`, `/notices`를 활용할 수 있다. 연구소 소개는 공식 원문을 갖춰 추가할 항목이다. 토론 경로는 기능을 실제로 시작할 때 결정한다.

자료 상세에서는 제목·자료 종류·출처→본문→해설과 연구 질문→관련 연구 글→향후 연결 토론 순으로 이어진다. 연구 글 상세에서는 저자·유형·상태→논지와 근거→관련 자료→향후 질문·응답을 둔다. 토론을 붙여도 자료와 연구 글의 주소는 안정적으로 유지한다.

## 5. 양방향 참여의 최소 확장안

| 단계 | 도입 범위 | 시작 조건 |
|---|---|---|
| 지금 | 기존 승인 회원 연구 글을 더 잘 발견하게 하고, 주제·자료와 연결 | 실제 글과 공개 기준 확인 |
| 다음 | 자료/연구 글에 연결된 질문 하나와 답변 흐름 | 운영 담당자·참여 권한·신고와 비공개 처리 기준 합의 |
| 이후 | 주제별 토론 목록과 검토 정리 | 반복 참여자와 축적된 유의미한 질문이 생겼을 때 |

첫 토론 버전은 제목, 질문 본문, 근거 자료 링크, 응답, 작성자·작성/수정 시각 정도로 시작한다. 공개 열람과 로그인 후 작성이 가능한 모델을 후보로 검토하되 권한 정책은 아직 결정된 것으로 취급하지 않는다. 채팅·좋아요 순위·활동 점수·복잡한 그룹은 현재 요구에 필요하지 않다.

근거 추가, 해석 질문, 다른 해석 제시처럼 학술적 기여의 형태를 안내하되, 모든 응답을 무조건 출처가 필요한 주장으로 취급하지 않는다. 출처가 필요한 사실 주장과 확인을 요청하는 질문을 구분한다. 신고·운영자 숨김·편집 이력은 실제 토론을 열 때 필요한 운영 범위로 정의한다. 답변이 있다는 이유만으로 ‘학술 검증 완료’ 상태를 부여하지 않는다.

## 6. 시안 범위와 검수

새 시안은 연구 질문 선택→관련 자료 표시를 구현한다. 질문은 첨부안에서 가져온 편집 예시임을 표시하고, 실제 논문·작성자·토론 건수를 만들지 않는다. 디자인 조절에서 ‘향후 토론 구상’을 켜면 근거에 연결된 질문·응답 배치를 볼 수 있다. 토론은 설명용 예시이며 저장·게시·접수 기능은 없다.

검수 기준은 320/390/1024px에서 수평 넘침이 없는지, 키보드로 주제를 선택할 수 있는지, 현재 기능과 미래 구상 표시가 구별되는지, 질문 변경 시 자료 맥락이 함께 바뀌는지다. 전체 배포용 접근성·서버 기능 테스트를 대신하지 않는다.

검증 결과: 브라우저에서 ‘업적 연구’ 선택 후 히어로 질문·자료 제목·설명·날짜가 함께 바뀌는 것을 확인했다. 320/390/1024px 미리보기에서 시안 루트의 scrollWidth와 clientWidth가 각각 일치했다. 호스트의 디자인 조절을 통한 미래 토론 전환과 전체 키보드 탐색은 이번 브라우저 검증에 포함하지 않았다.

원문 확보 이전에도 색·여백·메뉴·모바일 결함을 개선할 수 있다. 연구 원칙과 실제 과제 내용은 기관에서 확정한 문구로 반영하며, 토론 기능의 구현은 이후 별도 작업으로 진행한다.
